02

UI/UX review findings

Blocker

The given dashboard URL serves a blank page

https://dev.evenuefy.com/dashboard/ renders solid white. The old build deployed under /dashboard/ ships an index.html with <base href="/">, so the browser requests its bundles (main.ba5d7a45…js, styles.4c0a4b…css) from the site root — where they don't exist. The SPA fallback returns HTML for those requests and the browser blocks them as MIME-type errors. The bundles do exist under /dashboard/.

Fix: either rebuild that app with --base-href /dashboard/, or 301-redirect /dashboard/ to the root app (which works and appears to be the current build). Anyone following the shared login URL today sees a dead page.

High

Login "Continue" stays disabled after typing a valid email

On step 1 of login, typing a full valid email leaves the Continue button disabled; the control only enables after an extra Enter keypress re-triggers validation. The input showed ng-valid ng-dirty while the surrounding form stayed ng-pristine ng-invalid — the button's disabled binding is watching a form group the visible control doesn't update on input. Users who type and click (the majority) will believe login is broken.

High

Icon-only sidebar hides the product

The sidebar loads collapsed with unlabeled icons and no tooltips surfaced on the collapsed state. First-time exhibitors cannot find Badges or Vehicle Pass without expanding — and the expand affordance is a small chevron. Recommend labels-on by default for first session, or persistent tooltips. This matters more once Co-Exhibitors is added: a brand-new menu nobody has seen must be findable.

Medium

Naming and copy inconsistencies

  • Route typo: /app/vehical-pass ("vehical" → "vehicle"). Cosmetic in the URL bar, but it leaks into analytics and support docs.
  • Badges page route is /app/manage-exhibitor — after this project adds real co-exhibitor management, that name will collide. Consider /app/badges.
  • The quota modal is titled "Ticket / Parent User Selection" — internal jargon. Exhibitors think in "badge categories", not parent users.
  • Company name renders with broken casing in tables: "Hindustan Aeronautics Limited (Hal)" — a titlecase pipe is mangling the stored acronym "(HAL)".
  • Two-digit years in tables ("24 Jul, 26") read ambiguously; use "24 Jul 2026".
Medium

Passes are scattered across the menu

"Exhibitor Badges" and "Vehicle Pass" sit as unrelated top-level items, and the planned Exhibitor Invitee passes would make a third. The requirement already groups them: introduce a single Passes menu with three sub-items (section 03). This shortens the sidebar and matches the exhibitor's mental model — "everything that gets a person or vehicle through the gate".

Works well

Patterns worth reusing for Co-Exhibitors

The quota card pattern (allocated / used / available with a usage progress bar), status chips on My Spaces, and the searchable registrant table are clear and already familiar to exhibitors. The Co-Exhibitor screens below deliberately reuse all three rather than inventing new patterns.

03

New information architecture

Two changes to the exhibitor sidebar: a new Co-Exhibitors main menu, and the pass-related items consolidated under one Passes menu.

Gating rule: the Co-Exhibitors menu is enabled only when the exhibitor has at least one confirmed (booked & paid) space. Before that, show the menu disabled with a tooltip: "Available after your space booking is confirmed." This enforces requirement #1 — book first, then distribute.

4.3 · Validation

  • Email must be unique across exhibitors and co-exhibitors for the event.
  • Duplicate company-name warning (non-blocking) within the same exhibitor.
  • Type cannot be changed after creation if stall space or quotas are already allocated; require de-allocation first.

Rules

  • Editing an allocation re-runs the same remaining-area validation.
  • Removing an allocation returns the sqm to the stall's available pool. Block removal if the co-exhibitor still holds pass quotas tied to that space (or cascade with a confirm dialog — recommend block, with a message naming the quotas to release first).
  • The exhibitor's own effective area (booked − allocated out) should be visible on this screen and on My Spaces.

6.2 · Quota accounting rules

  • Assigning quota moves badges from the exhibitor's balance into a reserved co-exhibitor pool; the exhibitor's own "Available" figure drops immediately.
  • Quota can be increased any time (within balance) and decreased only down to the number already consumed.
  • The same Assign Quota pattern is reused verbatim for Invitee passes (07) and Vehicle passes (08) — build it once as a shared component.

6.3 · Co-exhibitor's own login (Separate type)

The co-exhibitor sees a reduced portal: Dashboard, Badge Details (only categories where quota was assigned, capped at that quota), and Vehicle Pass Details if assigned. No space booking, no co-exhibitor menu of their own, no ability to re-delegate quota.
